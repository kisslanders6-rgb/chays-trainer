# Chays Trainer : cadrage pour les assistants

À lire en début de session. Le README décrit l'application pour les humains ; ce fichier donne ce qu'il faut savoir pour modifier le code sans casser d'invariant. Mettez-le à jour dans le même commit quand vous ajoutez une clé de stockage, un nom global, un onglet ou une règle métier.

## Ce que fait l'application

Entraîneur d'échecs en français, PWA **sans dépendance d'exécution ni étape de compilation** : HTML, CSS et JS classiques chargés par `index.html`, dans un ordre qui compte (dépendances). Données dans `localStorage`, toujours via `dataStore` (`js/core/storageAdapter.js`). Synchronisation facultative avec Supabase (`supabase/schema.sql`, `js/core/sync*.js`, `cloud*.js`, `auth.js`). Déploiement statique (Vercel).

- **Jouer** (`js/modules/openings/`) : on joue ses coups et ceux de l'adversaire. Dans une position inconnue, mon coup devient l'unique réponse enregistrée. Rien n'y est compté (ni statistiques ni révisions). Reçu de coup : la barre d'état confirme l'enregistrement (`_showReceipt`) et propose « Annuler » (`undoRecordedMove`, sans confirmation, l'entrée va à la corbeille) tant que la position affichée est celle d'après ce coup ; sinon « Corriger » (`undoMove`, avec confirmation). Au trait adverse, `renderOppSuites` (`moveStats.js`) montre les trois suites les plus jouées (`_freqRows`, action `freqPlay`). L'Indice est désactivé, raison en infobulle, au trait adverse ou dans une position inconnue (`_hintBlocked`).
- **Entraînement** (`js/modules/training/`) : répétition espacée, exercices (révision du jour, points faibles, ligne complète, à confirmer, contre-la-montre, mode libre), séances avec bilan. Seul cet onglet fait évoluer statistiques et révisions. Menu « Rampe » (lot 7, `trainingUI.js`) : bilan de la dernière séance (anneau du premier coup, puces, liste avant → après repliée sur téléphone), Révision du jour, exercices puis maîtrise ; un seul bouton plein, choisi par `_trPrimary` (dues → erreurs à revoir → exercice mis en avant → Points faibles) ; filtre d'ouverture en puce `#training-filter` dans la barre de contexte ; Ligne complète et Mode libre se déplient sur place (le Mode libre se lance par son bouton). En séance : pastille « Toucher pour passer » pendant la mise en situation, `#tr-progress` logé dans la marge du haut à partir de 920 px (0 px net, `--board-chrome-h` inchangé).
- **Statistiques** (`js/modules/stats/`) : maîtrise en cinq niveaux plus l'état « À confirmer » (hors des barres), ouvertures nommées, régularité. Les Statistiques observent, l'Entraînement agit : leurs boutons ouvrent l'exercice d'Entraînement filtré (`openTrainingFrom`, filtre d'ouverture `_trOpening`) sans lancer de séance ; seul « S'entraîner » sur une position précise lance une révision. Aperçu d'une position (`openStatsPreview`, mode `preview`) : la barre du haut remplace répertoire et couleur par « ‹ Statistiques » (`statsBack`, qui rouvre la page au même défilement) et la puce `.lv-chip` du niveau, suivie de la liste quittée (`data-origin`). Dans `index.html`, `data-modes` montre un élément dans ces modes, `data-modes-not` le cache (`applyModeUI`). Lot 7 : une seule action pleine (Révision du jour, ou Points faibles quand tout est à jour) ; `levelBarHTML(counts, cls, { buttons, active })` rend une barre cliquable qui filtre comme la légende ; prévision sur 7 jours (`dueForecast`) ; règle de chaque niveau en `title` de la légende (plus de bulle ⓘ) ; points faibles avec mini-échiquier, la ligne ouvre l'aperçu ; états vides ; faits de l'aperçu `#stats-facts` dans le panneau latéral (ordinateur) ; calendrier sur 12 semaines, 5 sur téléphone (`.old`).
- **Finales** (`js/modules/endgame/`) : moteur maison `EG` (`egCore.js`), base exacte roi + pion contre roi, catalogue `egExercises.js`. Un exercice sans `kind` est **jugé** : `EndgameJudge.probe(fen)` (`egJudge.js` : KPK locale, sinon tables Syzygy de l'API Lichess jusqu'à 7 pièces, réponses gardées dans IndexedDB `chays-tablebase`, sinon `Engine` avec seuils +2,5 / 0,6, verdict « estimé ») ; erreur si le résultat se dégrade (`_egJudgedOutcome`). Adversaire : `EndgameOpponent.pick(fen, appSettings.egOpponent)` (`egOpponent.js`, 'max' ou 'human'). Mats, `kpk` et `pawns` gardent leurs juges locaux. Les verdicts des exercices jugés sont figés dans `ENDGAME_VERDICTS` par `node scripts/check-endgames.mjs` (réseau requis) : à relancer après toute modification d'une FEN, sinon `endgameSelfTest` échoue. Accueil « Bibliothèque » (lot 7) : puces `Ring.chip` par catégorie (action `egJump`), lignes bord à bord sous 720 px puis cartes ; toucher un exercice ouvre un aperçu (panneau du bas sous 920 px, colonne de droite au-delà) dont « Commencer » est la seule action pleine. En séance : verdict « avant → après » (`.eg-verdict`, `endgameState.verdict`), origine du jugement en `.vbadge` (« Réponse gardée » = Syzygy hors ligne), jauge d'un cran par coup à tenir, théorie repliée (`egTheory`).
- **Analyser mes parties** (`gameReview.js`, `onlineGames.js`) : parties Lichess / Chess.com / PGN collé, arrêt au premier coup hors répertoire, tout passe par `reviewGame`. Mon coup différent : erreur comptée une fois par partie, répertoire et couleur. Coup adverse non couvert : nouveauté, rien de compté. Déviation couverte par une réponse enregistrée **après** la partie : « Traitée depuis », rien de compté, réponse prioritaire en révision tant qu'elle n'a pas été réussie. Chaque partie est notée au journal synchronisé `chessTrainer_gameLedger` (« déjà analysée »). « Boîte de réception » (lot 7) : source en segments (Lichess / Chess.com / PGN collé), nombre de parties en segment, formulaire replié en ligne de source (`#online-done`) ; compteurs filtrants (`ONLINE_FILTERS`) ; verdict → `.vbadge` par `ONLINE_VERDICTS` / `onlineVerdictKey` (« Sans réponse » = nouveauté déjà repérée) ; « comptée » seulement si `row.counted === 'counted'`, « déjà » sinon ; dès 920 px un clic choisit la partie (détail à droite, « Ouvrir dans Jouer »), sur téléphone il ouvre Jouer ; export Lichess avec `opening=true` (`lichessExportUrl`), ouverture lue par `onlineOpening`. « Dernière analyse » : mémoire de session seulement.
- **Analyse** (`js/modules/analysis/analysis.js`, `gameMode === 'analysis'`) : l'écran de jeu avec les deux camps libres, Stockfish (`js/core/engine.js`) et un brouillon en arbre (sessionStorage). Rien n'est écrit dans le répertoire avant « Ajouter au répertoire » (`analysisMergePlan`, mêmes règles que l'import PGN). `executePlayerMove` aiguille les coups vers `analysisMove`, `navGo` prévient `analysisPositionChanged`. « Arrêter » ne suspend que la position affichée (`analysis.paused`) : la suivante est recalculée, sinon l'évaluation Lichess (cloud-eval) masquerait un moteur à l'arrêt ; un calcul annulé par le moteur est relancé indéfiniment (4 essais rapprochés, puis toutes les 10 s). Brouillon annoté (lot 7) : quatre marques calculées par `analysisMarks` (nouveau, connu, conflit, à remplacer), coups adverses sans marque ; « Ajouter au répertoire (N) », N = écritures (`analysisPlanSummary`), désactivé avec « Rien à ajouter » ; l'aperçu s'ouvre sur « Toutes les branches » (tiroir du bas sur téléphone), un losange ambre l'ouvre sur son conflit ; les puces du moteur ouvrent `showSettings('moteur')`.
- **Moteur** : `engine/manifest.json` (version, variantes lite / lite-single, empreintes) ; `Engine.analyse(fen, { multipv, depth, movetime }, onInfo)` renvoie `{ stop(), done }` (`depth` et `movetime` combinés dans un même `go`), scores du point de vue des Blancs, un seul calcul à la fois. stockfish.js met `go` en file mais exécute `stop` tout de suite : `stop` est renvoyé tant que le calcul arrêté parle, et sans `bestmove` après le délai `grace` le Worker est recréé en gardant le calcul en attente (`restart`, erreur après 3 échecs) ; `uciok` / `readyok` ont un délai (`tests/engineQueue.test.js`, faux Worker). L'Analyse relance le moteur 120 ms après le dernier changement de position. Multi-thread seulement si `crossOriginIsolated` (en-têtes de `vercel.json` : COOP `same-origin`, COEP `credentialless`). Ne pas passer COEP à `require-corp` : les polices Google, servies en réponse opaque par le service worker, seraient bloquées. Safari ignore `credentialless` : moteur mono-thread, rien d'autre ne change. Réseau `appSettings.engineNet` (propre à l'appareil) : `lite` embarqué, ou `full` dont le `.wasm` de 99 Mo vient d'unpkg (`Engine.full.download()`, sha256 vérifié, cache `chays-engine`, passé au Worker en `blob:` dans le fragment `#` du script ; `sw.js` range les fichiers du moteur sans fragment et les rend dans une réponse neuve, sinon le Worker lirait le blob révoqué du premier chargement et attendrait sans fin, `tests/swEngine.test.js`) ; jamais de `.wasm` complet dans le dépôt. Changer de réseau : `Engine.reload()` (un chargement en cours est abandonné via le compteur `gen`). Mise à jour : `scripts/update-engine.mjs` et `.github/workflows/engine-update.yml`.
- **Annonce des coups** (`sound.js`) : préférence locale `announce` = `'off'` | `'sr'` (région `#sr-moves` déclarée dans `index.html`, vidée puis écrite 60 ms plus tard) | `'voice'` (`Voice`, Web Speech, voix française si présente, débloquée au premier toucher). Phrase en toutes lettres par `spokenMove(san)` : prise, roques, promotion, échec, mat. L'ancien interrupteur booléen est converti au chargement.
- **Fenêtres** Paramètres, Aide, Compte : socle commun `js/core/panelKit.js`. Grilles de choix (`.theme-options`) : `--cols` posé par `PanelKit.balancedCols` selon la largeur et le nombre de tuiles (pas de tuile seule en dernière ligne quand c'est évitable, sinon centrée). « Pièces invisibles » est un interrupteur (clé d'affichage `blindfold`, qui écrit `pieceSet`), hors de la grille des pièces. Paramètres « Établi » (lot 7) : pas de phrase d'aide (`tip` = infobulle du libellé), repère local `PanelKit.localMark()` calculé depuis `LOCAL_PREFS` (aussi en marge d'une rubrique entièrement locale, `local: true`), aperçu d'Apparence en direct (`drawArrows`, position après 3. Fb5), recherche dont les résultats se règlent sur place, `data-min` / `data-max` des grilles lus par `fitGrids`, `showSettings(section, pref?)`. Aide « Sommaire vivant » (`helpUI.js`) : accueil (trois étapes, `HELP_TASKS`, guides), guides en objets `HELP_GUIDES` avec puce de comptage (`.vbadge`) et un seul bouton plein vers `HELP_TARGETS` (action enregistrée) ; recherche groupée Tâches › Guides › Questions › Raccourcis, ↑ ↓ Entrée Échap, focus sauf pointeur tactile ; un guide ne dit jamais que Jouer compte (`tests/helpGuides.test.js`).
- **Accueil Jouer** : barre de contexte collante (`.st-scope`, comme Statistiques et Entraînement) avec la puce du répertoire, les pastilles des autres répertoires (`HP_QUICK_MAX`, masquées sur téléphone), les outils (Analyser mes parties, Importer) et le menu ⋮ ; le répertoire ne s'affiche qu'à cet endroit. Trois blocs, dans cet ordre sur téléphone : « Aujourd'hui » (`#hp-today`, `renderHomeSummary`, `app.js`), « Jouer » (Blancs / Noirs avec leur première position et la barre de maîtrise `levelBarHTML`, Reprendre) et « À traiter » (`HomePanels`, `homePanels.js` : vues Nouveautés — journal des parties, verdict `novelty` / `out` avec `path`, tant que la réponse manque — et Parties). « Aujourd'hui » n'a qu'une action selon l'état : positions dues → « Commencer la révision » (`startDailyReview`, `trainingUI.js` : Révision du jour, les deux couleurs, sans filtre d'ouverture ; c'est une séance d'Entraînement, elle compte) ; à jour → « Ajouter une ligne » dans la couleur la moins fournie ; répertoire vide (`#hp-grid.is-empty`) → choix de la couleur. Il montre la position due la plus en retard (`_miniBoardHTML`), l'objectif du jour en anneau, la série, et le programme par ouverture (`_assignOpenings`). Au-delà de 1 000 px (requête de conteneur `home-play`, `css/home.css`) : Aujourd'hui à gauche, Jouer et À traiter à droite ; sous 600 px, blocs bord à bord. Statistiques sur téléphone : requête de conteneur `stats` (trois chiffres, onglets Aperçu / Ouvertures / Régularité). Lot 7 : « Aujourd'hui » se lit de haut en bas (surtitre, chiffre dû et anneau `Ring`, position la plus en retard, unique `.btn-primary`, puis « Au programme » ou, à jour, la prévision sur 7 jours `dueForecast`) ; « Autres exercices » ouvre l'onglet Entraînement ; répertoire vide : deux cartes à choisir puis « Commencer avec les … » (`homePick`) ; À traiter : badges `.vbadge` et bouton « Répondre » (`homeGameAnswer` dans la vue Parties).

## Modèle de données (invariants)

- Une position = `positionKey` : « pièces trait roques passant ». Le répertoire est indexé par position : les transpositions sont naturelles.
- Base d'un répertoire et d'une couleur : `{ [positionKey]: entrée }`, lue par `readDBFor(rep, couleur)`. Une entrée = MA réponse unique `{ move (UCI), san (anglais), attempts, failures, path, ply, due, interval, created?, prio? }` (`newEntry`, `normalizeEntry`, `js/storage.js`). `created` : date d'enregistrement (absente avant octobre 2026). `prio` : réponse « Traitée depuis » jamais réussie, levée par `recordReview(e, true)`. Tout nouveau champ d'entrée doit être gardé par `normalizeEntry` ET par la fusion de `syncModel.js` (`combineSameMove`), sinon il disparaît. Les coups adverses ne sont jamais des entrées : ils ouvrent des branches ; `oppSeen` garde ceux qui ont été repérés.
- Les coups sont stockés en notation anglaise ; `formatSan(san, couleur)` renvoie du **HTML échappé** (figurines : `<span class="fig">` du jeu actif, variables `--fig-wN`… posées par `applyPieceSet`), `formatSanText` du texte simple (barre d'état, `title`, copie), en lettres même en mode Figurines (plus de glyphes Unicode ♘, rendus en emojis). Toute liste affichée (Nouveautés, parties en ligne, Statistiques, rapport PGN, aperçu de fusion) passe par `formatSan` ou l'option `html` de `formatLinePrefix` / `_plyLabel`. Ne jamais repasser `formatSan` dans `escapeHtml`. Le jeu « Invisibles » repasse aux lettres.
- Préférences (`js/core/settings.js`) : `SYNCED_PREFS` (chaque champ daté, la plus récente gagne entre appareils) et `LOCAL_PREFS` (propres à l'appareil). Chacune doit avoir son réglage dans `settingsUI.js` ou `accountUI.js` (test). Les options du mode libre sont `freeMaxPlies`, `freeSeqLen`, `freeFromStart` (lues via `trainingSettings`). Le niveau du profil a été retiré. Défauts d'apparence : Noyer (`walnut`) + Maestro pour les nouvelles installations ; une installation antérieure garde Sauge (`classic`, anciennement « Vert classique ») + Merida (`keepOldLookDefaults`).
- Clés synchronisées : liste dans `js/core/syncModel.js`. Toute nouvelle clé à synchroniser doit y être déclarée, sinon elle reste sur l'appareil.
- `chessTrainer_timedRecord` (record du contre-la-montre) est synchronisé : le plus grand l'emporte.
- Clés seulement locales notables : `chessTrainer_mode` (clair / sombre / système), `chessTrainer_avatarLocal` (photo de 128 px), `chessTrainer_looksDefaults`, `chessTrainer_looksTip` (suggestion Noyer + Maestro déjà vue), `chessTrainer_authFlow` (démarche de compte lancée sur cet appareil, 24 h : sans elle, un lien `#access_token=…` n'est appliqué qu'après confirmation du compte nommé, et les données ne partent qu'après le choix « Première synchronisation »), `chessTrainer_reviewedGames` (ancienne liste des erreurs comptées, seulement relue), `chessTrainer_splashDay` (jour de la dernière animation de lancement complète, « la plume » ; ensuite « la gravure », courte, via `html.splash-quick` posé par le script de tête ; `tests/splash.test.js`). Convention : `chessTrainer_<nom>` ; les anciennes clés `chessTrainer.trainingSettings`, `chessTrainer.timedRecord` et `chessTrainer_theme` sont converties au démarrage puis supprimées.

## Pièges connus

- **Texte discret** (`--text-dim`) : relevé au lot 7 pour 4,5:1 sur `--surface` ET `--bg-elevated` (sombre neutre #8e9195, night #8592a4, oled #8a8a8a, green #8b9682, clair #62675a) ; vérifié par `tests/theme.test.js`.
- **Fond du mode sombre** : préférence synchronisée `darkBg` (`DARK_BGS` : `neutral` par défaut, `night`, `oled`, `green` = l'ancien vert « Nocturne »), posée en `data-dark` sur `<html>` par `applyDisplayPrefs` et par le script de tête d'`index.html`. Le gris neutre est le bloc `[data-theme="dark"]` de `style.css` ; les autres le surchargent (`html[data-theme="dark"][data-dark="…"]`, voile `--overlay`), et le contraste renforcé a sa variante par fond (`panels.css`). `tests/theme.test.js` lit les quatre fonds dans `style.css`.
- **Barre système** (`<meta name="theme-color">`) : `themeColor.js` écrit toujours du `#rrggbb` (élément témoin + canvas 1×1), jamais la valeur brute d'une variable (`getPropertyValue('--accent')` rend la formule `oklch(from …)`, refusée). En sombre, le script de tête d'`index.html` pose dès le lancement le fond choisi (table `bars`, vérifiée contre `style.css` par `tests/theme.test.js`).
- **Couleurs d'accent** : `--ui-accent` (donc `--accent`) et `--board-ring` sont dérivés de `--board-dark` (`style.css`, « HARMONISATION ») ; n'écrivez pas d'accent par échiquier. En sombre, l'accent est clair et `--accent-text` foncé. `tests/theme.test.js` recopie ces formules et vérifie 4,5:1 sur les 13 échiquiers × (clair + 4 fonds sombres) ; `tests/theme-matrix.html` sert au contrôle visuel. Nouvel échiquier texturé : `scripts/gen-boards.mjs` (sharp hors dépôt), puis `BOARD_THEMES`, `BOARD_LABELS`, `style.css`, `css/panels.css`, `sw.js`.
- **Animation des coups** : `animateNextMove(from, to)` arme l'animation consommée par le prochain `renderBoard()` (reconstruit en `innerHTML` : un rendu pendant l'animation la relance au même instant via `_liveAnim` / `_resumeMoveAnim`, tant que la position affichée n'a pas changé ; `tests/boot.test.js`). Durée commune `moveAnimMs()` (0 si coupée ou mouvement réduit) ; `opponentDelay()` n'est jamais plus court que `moveAnimMs() + 30`. Un pas de navigation (◀ ▶) et `loadPositionFromPath(moves, { animateLast: true })` (contre-la-montre) animent aussi le coup.
- **Écran de jeu (lot 7)** : `setStatus(msg, type, detail, { action, run, icon?, title? })` ajoute un bouton `.status-act` à droite de la barre d'état, retiré par l'appel suivant ; `showBoardPill(text, onTap?)` / `hideBoardPill()` posent une pastille sur l'échiquier (`#board-pill`, hors du flux). À partir de 920 px, ‹ action › et les outils (`.controls-tools`, icônes, libellé lu par les lecteurs d'écran) tiennent sur une seule rangée de 48 px : un outil de plus s'ajoute dans le `.controls-tools` du mode sans changer de hauteur. Section « ÉCRAN DE JEU (LOT 7) » de `style.css`.
- **Taille de l'échiquier (920px+)** : `--bw` (largeur des 8 cases, sans le liseré) = la plus petite place entre largeur laissée au panneau et hauteur sous la barre du haut, entre 512 et 960 px, arrondie à 8 px (`style.css`, « ÉCHIQUIER À LA TAILLE DE L'ÉCRAN »). Le bloc doit rester après `.sq { width: 64px … }` (même spécificité) ; tout élément ajouté au-dessus ou au-dessous de l'échiquier se compte dans `--board-chrome-h` (116 px : 28 + 4 + 4 de liseré + 16 + 48 de contrôles + 16 ; 134 px avec les coordonnées extérieures ; `tests/layout.test.js`).
- **Flèches** : `drawArrows({ arrows, circles, style, flipped, knight })` (`annotations.js`) est pure ; l'échiquier et l'aperçu d'Apparence l'utilisent.
- **Thème** : `chessTrainer_mode` vaut `'dark'` (défaut), `'light'` ou `'system'` ; `data-theme` sur `<html>` vaut `'dark'` ou `'light'`, dans le CSS comme en JS. L'ancienne clé `chessTrainer_theme` avait des valeurs inversées (`'light'` = sombre) : `settings.js` la convertit, le script en tête d'`index.html` la lit encore en repli. Passer par `themeMode()` / `setThemeMode()`.
- Pour calculer sur une autre position que celle affichée : API `Chess` (`Chess.replay`, `Chess.play`, `Chess.san`, `Chess.key`, `Chess.snapshot`), jamais l'état global `board` / `turn`. Les lectures PGN passent par `_withEngineSnapshot`.
- `Chess.fen(pos)` donne la FEN d'une position (`displayedFen()` pour celle affichée).
- PGN (`pgn.js`) : les numéros de coup sont lus. Un numéro qui revient en arrière (`12. Cf3 Cd7 12... Cf6`) ouvre une **variante implicite** (`implicit: true`), comme des parenthèses.
- Icônes : le sprite `_ICONS` (`icons.js`) ; ne renommez pas une icône sans ses usages (`tests/icons.test.js` vérifie chaque `#i-…` et `ico(…)`).
- Un seul nom global par script (de préférence un objet, comme `Chess`, `EG`, `SyncModel`) : `npm test` refuse un nom déclaré deux fois.
- Nouveau script : l'ajouter dans `index.html` ; `sw.js` le met en cache tout seul. Image remplacée : incrémenter `VERSION` dans `sw.js`.
- Icônes de l'app : PNG 192, 512, masquable et iOS par `swift scripts/export-icons.swift` (`assets/brand/chays-icone.svg`) ; `favicon.ico` (16, 32, 48 px, `assets/brand/chays-favicon.svg`) et `icon-mono-512.png` (manifeste `monochrome`) par `swift scripts/export-favicons.swift` ; `assets/icons/icon.svg` est le favicon adaptatif clair / sombre, écrit à la main (croix épaissie, sans gravure). `tests/pwaIcons.test.js` vérifie balises, manifeste et cache.
- Le script en ligne en tête d'`index.html` applique thème et échiquier avant le premier rendu : le garder cohérent avec `settings.js`.
- Panneaux (`css/panels.css`) : `.pn-content` est une colonne flex qui défile ; ses enfants ont `flex-shrink: 0`, sinon les volets en `overflow: hidden` sont écrasés.

## Conventions

- Français partout : interface, commentaires, messages de commit. Notation française à l'écran (C F T D R).
- En-tête de fichier qui explique le rôle du module ; sections `// ─── TITRE ───` ; commentaires courts, en phrases.
- Pas de framework, pas de bundler. `jsdom` sert uniquement aux tests.
- Les actions de l'interface passent par `onclick` dans `index.html` ou par `data-action` + `registerActions` (`js/core/utils.js`).
- Échapper tout texte inséré en HTML (`escapeHtml`).

## Tests

`npm test` (`tests/run.js`, Node, aucun réseau : serveur Supabase simulé). `boot.test.js` charge `index.html` entier dans jsdom ; `globals.test.js` vérifie les noms globaux. Chaque règle métier (PGN, révision, synchronisation, finales, préférences) a son test : en ajouter un avec toute nouvelle règle. Les tests tournent à chaque push (`.github/workflows/tests.yml`).

Prévisualisation locale : `.claude/launch.json` (serveur Node sur le port 8080) ou `npm start`.

Skills du projet (`.claude/skills/`) : `cloture-lot` (vérifications et commit de fin de lot), `nouvelle-donnee` (champ d'entrée, clé de stockage, préférence), `exercice-finale` (catalogue des finales et verdicts), `apparence-ajout` (échiquier, jeu de pièces, style de flèches). Les tenir à jour quand une procédure qu'elles décrivent change.
