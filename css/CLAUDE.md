# Styles (css/)

Thèmes, ambiances, contrastes et compatibilité Safari. Feuilles principales, chargées dans cet ordre par `index.html` (la cascade en dépend) : `base.css` (variables, thèmes, ambiances), `layout.css` (mise en page, écrans), `components.css` (badges, boutons, icônes, anneaux), `board.css` (pièces, échiquiers texturés, taille de l'échiquier), `game.css` (écran de jeu détaillé, Analyse, dock, tablette) ; puis `home.css`, `screens.css`, `account.css`, `panels.css`, `feedback.css`. Les tests relisent l'ensemble avec `mainCss()` (`tests/_app.js`).

- **Jetons (identité « Noyer gravé »)** dans `base.css` : `--dur-1` 120 ms (retour d'un geste), `--dur-2` 220 ms (surface qui arrive), `--dur-3` 420 ms (progression, case d'erreur) ; `--ease-out` (arrivée) et `--ease-move` (déplacement). Toute nouvelle transition prend un de ces jetons ; seul `splash.css` garde ses temps. Polices : `--font-sans` (Inter), `--font-display` (Fraunces), `--font-note` (IBM Plex Mono, 400 à 700) ; plus de `--font-mono` ni de `--font-serif`. Animations communes : `surfaceIn` (menus, listes, palette, panneaux ; `--in-y`, `--in-s`), `sheetUp` (feuilles du bas ; `--sheet-from`), `spin` (seule toupie, `reverse` pour les icônes de rotation). Coup refusé : la pièce revient (`.piece.is-refused`, `flashWrong(to, from)`), plus de secousse de l'échiquier.
- **Couleurs de marque** (`--brand-walnut`, `--brand-ink`, `--brand-cream`, `--brand-grave`, `--brand-brass`, `--brand-brass-deep`, `base.css`) : fixes, jamais tirées de l'échiquier. Le logo (`--ct-*`, `game.css`) les utilise en clair comme en sombre ; les commandes gardent l'accent dérivé de l'échiquier.
- **Texte discret** (`--text-dim`) : relevé au lot 7 pour 4,5:1 sur `--surface` ET `--bg-elevated` (sombre neutre #8e9195, night #8592a4, oled #8a8a8a, green #8b9682, clair #62675a) ; vérifié par `tests/app/theme.test.js`.
- **Ambiance** (point 13) : préférence synchronisée `darkBg` (clé gardée pour la synchronisation ; `DARK_BGS` : `buis` par défaut des nouvelles installations, `board` gardé par les antérieures, `neutral`, `green`, `night`, `oled`), posée en `data-dark` sur `<html>` par `applyDisplayPrefs` et par le script de tête d'`index.html`, en clair comme en sombre. Chaque ambiance apparie un jour et une nuit (`css/`, « AMBIANCES ») : Buis = buis / noyer, les bois de la marque, valeurs fixes ; Échiquier = papier et ardoise teintés par `--board-dark` (clarté fixe, chroma plafonnée, `oklch(from …)` dans `@supports`, repli Neutre légèrement teinté) ; Neutre = blanc cassé / gris neutre (bloc `[data-theme="dark"]`) ; Papier = crème (`:root`) / vert « Nocturne » ; Brume = brume bleutée / bleu nuit ; Encre = blanc / noir OLED. Jours : `html:not([data-theme="dark"])[data-dark="…"]` ; nuits : `html[data-theme="dark"][data-dark="…"]` (voile `--overlay`). Contraste renforcé par fond dans `panels.css`. `tests/app/theme.test.js` lit toutes les palettes et recopie les formules d'Échiquier (20 échiquiers × clair et sombre).
- **Barre système** (`<meta name="theme-color">`) : `themeColor.js` écrit toujours du `#rrggbb` (élément témoin + canvas 1×1), jamais la valeur brute d'une variable (`getPropertyValue('--accent')` rend la formule `oklch(from …)`, refusée). En sombre, le script de tête d'`index.html` pose dès le lancement le fond choisi (table `bars`, vérifiée contre `css/` par `tests/app/theme.test.js` ; Échiquier, calculé, prend le gris neutre jusqu'à `themeColor.js`).
- **Couleurs d'accent** : `--ui-accent` (donc `--accent`) et `--board-ring` sont dérivés de `--board-dark` (`css/`, « HARMONISATION ») ; n'écrivez pas d'accent par échiquier. En sombre, l'accent est clair et `--accent-text` foncé. `tests/app/theme.test.js` recopie ces formules et vérifie 4,5:1 sur les 20 échiquiers × (5 ambiances en clair et en sombre) ; `tests/theme-matrix.html` sert au contrôle visuel. Échiquier en aplat : le damier est dessiné sous les cases (`#board`, dégradé conique, cases transparentes), sinon les surlignages translucides se posent sur le fond sombre (section « CATALOGUE : NOUVEAUX ÉCHIQUIERS » de `css/`). Nouvel échiquier texturé : `scripts/gen-boards.mjs` (sharp hors dépôt), puis `BOARD_THEMES`, `BOARD_LABELS`, `css/`, `css/panels.css`, `sw.js`.
- **Safari 16 (iOS 16, iPhone 8)** : il annonce reconnaître `oklch(from …)` (`CSS.supports` vrai) mais plante en le calculant (« Un problème récurrent est survenu »). Toute couleur relative vit dans `@supports (color: light-dark(red, red)) { … }` (Safari 17.5, Chrome 123, Firefox 120), précédée d'un repli `color-mix()` (accent clair : 52 % de `--board-dark` vers `#1a1208`, sombre : 48 % vers `#efe6d8`, 4,5:1 vérifié). `tests/app/theme.test.js` refuse un `oklch(from` hors de ce bloc dans toutes les feuilles.
- **Thème** : `chessTrainer_mode` vaut `'dark'` (défaut), `'light'` ou `'system'` ; `data-theme` sur `<html>` vaut `'dark'` ou `'light'`, dans le CSS comme en JS. L'ancienne clé `chessTrainer_theme` avait des valeurs inversées (`'light'` = sombre) : `settings.js` la convertit, le script en tête d'`index.html` la lit encore en repli. Passer par `themeMode()` / `setThemeMode()`.
- Panneaux (`css/panels.css`) : `.pn-content` est une colonne flex qui défile ; ses enfants ont `flex-shrink: 0`, sinon les volets en `overflow: hidden` sont écrasés.
