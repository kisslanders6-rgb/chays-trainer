# Styles (css/ et style.css)

Thèmes, ambiances, contrastes et compatibilité Safari.

- **Texte discret** (`--text-dim`) : relevé au lot 7 pour 4,5:1 sur `--surface` ET `--bg-elevated` (sombre neutre #8e9195, night #8592a4, oled #8a8a8a, green #8b9682, clair #62675a) ; vérifié par `tests/theme.test.js`.
- **Ambiance** (point 13) : préférence synchronisée `darkBg` (clé gardée pour la synchronisation ; `DARK_BGS` : `board` par défaut, `neutral`, `green`, `night`, `oled`), posée en `data-dark` sur `<html>` par `applyDisplayPrefs` et par le script de tête d'`index.html`, en clair comme en sombre. Chaque ambiance apparie un jour et une nuit (`style.css`, « AMBIANCES ») : Échiquier = papier et ardoise teintés par `--board-dark` (clarté fixe, chroma plafonnée, `oklch(from …)` dans `@supports`, repli Neutre légèrement teinté) ; Neutre = blanc cassé / gris neutre (bloc `[data-theme="dark"]`) ; Papier = crème (`:root`) / vert « Nocturne » ; Brume = brume bleutée / bleu nuit ; Encre = blanc / noir OLED. Jours : `html:not([data-theme="dark"])[data-dark="…"]` ; nuits : `html[data-theme="dark"][data-dark="…"]` (voile `--overlay`). Contraste renforcé par fond dans `panels.css`. `tests/theme.test.js` lit toutes les palettes et recopie les formules d'Échiquier (20 échiquiers × clair et sombre).
- **Barre système** (`<meta name="theme-color">`) : `themeColor.js` écrit toujours du `#rrggbb` (élément témoin + canvas 1×1), jamais la valeur brute d'une variable (`getPropertyValue('--accent')` rend la formule `oklch(from …)`, refusée). En sombre, le script de tête d'`index.html` pose dès le lancement le fond choisi (table `bars`, vérifiée contre `style.css` par `tests/theme.test.js` ; Échiquier, calculé, prend le gris neutre jusqu'à `themeColor.js`).
- **Couleurs d'accent** : `--ui-accent` (donc `--accent`) et `--board-ring` sont dérivés de `--board-dark` (`style.css`, « HARMONISATION ») ; n'écrivez pas d'accent par échiquier. En sombre, l'accent est clair et `--accent-text` foncé. `tests/theme.test.js` recopie ces formules et vérifie 4,5:1 sur les 20 échiquiers × (5 ambiances en clair et en sombre) ; `tests/theme-matrix.html` sert au contrôle visuel. Échiquier en aplat : le damier est dessiné sous les cases (`#board`, dégradé conique, cases transparentes), sinon les surlignages translucides se posent sur le fond sombre (section « CATALOGUE : NOUVEAUX ÉCHIQUIERS » de `style.css`). Nouvel échiquier texturé : `scripts/gen-boards.mjs` (sharp hors dépôt), puis `BOARD_THEMES`, `BOARD_LABELS`, `style.css`, `css/panels.css`, `sw.js`.
- **Safari 16 (iOS 16, iPhone 8)** : il annonce reconnaître `oklch(from …)` (`CSS.supports` vrai) mais plante en le calculant (« Un problème récurrent est survenu »). Toute couleur relative vit dans `@supports (color: light-dark(red, red)) { … }` (Safari 17.5, Chrome 123, Firefox 120), précédée d'un repli `color-mix()` (accent clair : 52 % de `--board-dark` vers `#1a1208`, sombre : 48 % vers `#efe6d8`, 4,5:1 vérifié). `tests/theme.test.js` refuse un `oklch(from` hors de ce bloc dans toutes les feuilles.
- **Thème** : `chessTrainer_mode` vaut `'dark'` (défaut), `'light'` ou `'system'` ; `data-theme` sur `<html>` vaut `'dark'` ou `'light'`, dans le CSS comme en JS. L'ancienne clé `chessTrainer_theme` avait des valeurs inversées (`'light'` = sombre) : `settings.js` la convertit, le script en tête d'`index.html` la lit encore en repli. Passer par `themeMode()` / `setThemeMode()`.
- Panneaux (`css/panels.css`) : `.pn-content` est une colonne flex qui défile ; ses enfants ont `flex-shrink: 0`, sinon les volets en `overflow: hidden` sont écrasés.
